## 关键设计决策

<a id="design-decisions"></a>

以下为当时提出的备选与AI推荐，随后实际选择见决定表。D09-A未采用；D09-B当前准确边界见[报告第4.5节](项目完成报告.md#concurrency)。

| 决策 | A 方案 | B 方案 | 其他备选 | AI 推荐 |
| --- | --- | --- | --- | --- |
| D01 技术栈 | Python FastAPI Pydantic PyMongo pytest，简单网页；校验与文档基础较好，需要统一浏览器与后端语义 | TypeScript Node.js 与网页；可共享类型，需要搭建相应校验与工具链 | C Java Spring Boot，类型与分层清楚，工程量较大 | A；熟悉其他技术时可调整 |
| D02 架构 | 同源网页与 REST API 的模块化单体；启动简单，规则和持久化独立 | 前端应用和后端独立构建部署；交互扩展方便，部署和跨域配置更多 | C 微服务，可独立扩容，当前运维与一致性负担较大 | A |
| D03 MongoDB Schema | 四集合 users、surveys、responses、sessions；题目选项规则内嵌，答卷独立；读取与原子修改边界清楚 | 再拆 questions、rules 集合；适合大问卷或题库，增加读取与发布一致性成本 | C 每份答卷带整份定义快照，历史清晰但冗余大 | A；含稳定ID、类型约束、十进制数字与索引草案 |
| D04 跳转语义 | 仅向后跳或结束，显式优先级第一条命中；确定且易测试，需要理解规则顺序 | 仅向后跳，要求规则互斥；不依赖优先级，但多选和区间冲突检测较复杂 | C 允许回跳与循环，表达力强，终止与历史答案语义复杂 | A；允许回看修改，上游改变后重算并清理不可达答案 |
| D05 匿名含义 | 填写者均先登录，可选择对创建者匿名；服务端用问卷内伪名限制重复，保留账号与匿名要求 | 匿名访客免登录；体验直接，但与“填写者需要先登录”有张力，同人识别也不可靠 | B 需先核实老师意图，不能悄悄取代原要求 | A；不承诺对系统运营者完全匿名 |
| D06 发布后的内容 | 第一阶段冻结题目、选项、规则及匿名与多次策略，保留内容版本；保护历史，首阶段范围小 | 第一阶段增加 survey_versions，允许新版本发布；扩展更早，但发布与会话绑定测试更多 | 不接受直接覆盖旧定义而破坏历史题意 | A；第二阶段若要求改题再迁移到版本集合 |
| D07 保存范围 | 每次下一题或修改完成后保存草稿，最终转正式答卷；覆盖保存要求更充分，增加状态API | 仅保存最终提交；工作量较小，未完成填写无法恢复 | 原文没有精确定义未完成保存，需明确选定解释 | A；无需逐键保存，界面说明保存时机 |
| D08 统计 | MongoDB 按正式答卷实时聚合；来源单一，便于核对，数据大时需性能评估 | 单独统计集合；读取快，需要幂等、校对、回填和重建 | 两者都应区分答卷数和独立账号数 | A |
| D09 关闭与提交并发 | 事务内更新问卷控制修订并提交答卷，关闭写同一问卷；语义严格，需要开发副本集和重试 | 最后一次服务端检查时受理，随后单文档提交；可用standalone，先受理请求可能在关闭返回后落库 | 两者都禁止在截止之后新受理，以服务端检查时间为准 | A，正确性优先；副本集部署需另行确定 |

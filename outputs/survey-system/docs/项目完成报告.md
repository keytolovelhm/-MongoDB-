## 1 项目目标与功能

创建者可以配置标题、说明、题目、选项、填写约束、跳转规则、匿名和多次填写策略，发布问卷并分享填写链接，也可以设置截止时间、关闭问卷和查看统计。填写者登录后按实际路径作答，可保存草稿、恢复进度并提交。系统支持单选、多选、文本填空和数字填空。

统计区分有效答卷数与独立填写账号数，提供整份问卷及单题结果、各选项次数、全部填写内容分页和数字平均值。统计只使用正式提交的数据。

## 2 系统设计

后端使用Python、FastAPI、Pydantic和同步PyMongo，前端使用同源HTML、CSS和JavaScript模块。所有账号、会话、问卷、草稿和正式答卷均存入MongoDB。

| 模块 | 职责 |
| --- | --- |
| app/main.py | REST接口、认证依赖、错误处理和静态页面 |
| auth_service.py、security.py | 注册登录、密码散列、会话、CSRF及问卷内伪名 |
| survey_service.py | 问卷编辑、发布、截止、关闭及版本检查 |
| attempt_service.py | 填写会话、逐题保存、路径重算与提交 |
| domain.py | 定义、答案及规则的校验与解释，不依赖数据库I/O |
| repositories.py、schema.py | MongoDB访问、BSON转换、验证器与索引 |
| stats_service.py | 根据正式答卷聚合统计和分页查询 |

接口、业务服务、规则和持久化分别组织，便于独立测试。前端无需构建服务；Node.js和jsdom仅用于可选DOM测试。后端同步数据库调用由同步接口处理。

## 3 MongoDB数据库设计

### 3.1 集合与文档边界

| 集合 | 文档单位 | 主要字段 |
| --- | --- | --- |
| users | 一个账号 | username、usernameNormalized、passwordHash、createdAt、schemaVersion |
| surveys | 一份问卷及完整定义 | ownerId、shareSlug、status、closesAt、参与策略、questions、contentVersion、ruleLanguageVersion、revision |
| responses | 一次填写 | surveyId、respondentKey、participationMode、repeatMode、attemptKey、answers、路径、revision、受理/提交时间 |
| sessions | 一次登录会话 | userId、tokenHash、createdAt、expiresAt |

题目、选项、约束和规则通常随问卷共同读取、编辑和发布，因此有界内嵌在surveys中。每次填写独立存入responses，并通过surveyId引用问卷，避免不断增长的答卷数组撑大问卷文档。单份答卷的答案共同保存，适合单文档条件更新。

采用关系数据库时，通常会将问卷、题目、选项、规则和答卷拆为独立表，通过外键及关联查询组织。两种方式都能满足需求，本项目选择按MongoDB的文档边界组织：整份问卷定义通常一起读取和发布，题目及选项有规模上限，适合内嵌；答卷数量随填写持续增长，适合独立存储。这样既减少读取定义时的关联操作，也避免把全部答卷装入单个问卷文档。结构和一致性由MongoDB验证器、业务校验及索引共同保证。

每份问卷最多200题，每题最多100个选项和50条规则，文本最多10000个码点；请求及BSON文档另有2 MiB大小限制。验证器完整定义见[mongodb-schema.json](mongodb-schema.json)，初始化由scripts/init_db.py及应用启动完成。

### 3.2 数据类型与稳定标识

题目、选项和规则分别使用questionId、optionId、ruleId，不以题号或文字作为引用。order只控制显示顺序，草稿排序不改变ID；服务端检查ID、顺序和规则优先级的唯一性。

单选答案使用selectedOptionId，多选使用selectedOptionIds，文本使用textValue，数字使用BSON Decimal128的numberValue。数字约束、规则阈值和API数字答案均使用十进制字符串传输，避免浮点精度损失。可选题显式留空保存为只有questionId的答案子文档，与尚未保存或未到达的题目区分。

### 3.3 索引与冗余

| 索引 | 用途 |
| --- | --- |
| users.usernameNormalized唯一 | 规范化用户名去重 |
| surveys.shareSlug唯一 | 分享入口唯一 |
| surveys：ownerId、updatedAt、_id | 个人问卷筛选与稳定分页 |
| responses：surveyId、status、contentVersion、submittedAt、_id | 统计过滤与答案分页 |
| responses：surveyId、respondentKey、attemptKey唯一 | 新建填写会话幂等 |
| responses：surveyId、respondentKey部分唯一 | 对SUBMITTED且SINGLE的答卷限制同账号一次提交 |
| sessions.tokenHash唯一、expiresAt TTL | 会话查找和过期清理 |

答卷不复制题干、选项文字或整份问卷定义，也不存储统计计数副本。contentVersion和repeatMode保留解释及重复限制所需的上下文；visitedQuestionIds保存最终路径，submissionDigest用于提交摘要。内嵌数组的ID唯一性由应用检查，普通唯一多键索引不能代替这一约束。第一阶段不提供硬删除，保留问卷与答卷的引用关系。

### 3.4 版本与历史数据

schemaVersion表示文档结构，contentVersion表示问卷题意，ruleLanguageVersion表示规则语义，identityKeyVersion表示伪名及密钥上下文；当前均为1。revision仅用于乐观锁，不是问卷历史快照。不支持的语义版本返回冲突。

发布后冻结题目、选项、规则、匿名和多次策略；截止与关闭不改变题意。已有冻结定义继续按原版本解释，新定义校验不会重写旧答卷。第二阶段如果允许发布后改题，应保留旧定义与旧解释，或制定可审计的迁移方案。

data/phase1-history-v1提供可恢复的合成历史基线：四集合数量为1/1/4/0，其中3份正式答卷对应2个伪名，另1份草稿不参与统计，数字均值为15。基线保留ObjectId、BSON Date和Decimal128，使用禁用账号且不含登录会话。恢复步骤见[README](../README.md#history-baseline)。

## 4 关键逻辑设计

### 4.1 题型与输入校验

单选必须引用本题选项，多选不得重复或引用其他题的选项。多选支持最少、最多和恰好N项，恰好N项表示为minSelections=maxSelections=N。文本按Unicode码点检查长度；数字检查范围、整数条件及Decimal128可表示性，拒绝NaN、Infinity、布尔值和错误JSON类型。手机号整数示例由数字题表达，不能保留前导零。

可选题留空不执行非空值约束；填写了值则完整校验。空数组只在多选中表示留空，不能作为文本或数字答案。必答多选最大数量为0、必答文本最大长度为0或矛盾区间等配置在保存和发布前拒绝。

### 4.2 条件跳转

规则保存在问卷数据中，由白名单解释器执行。单选支持按optionId相等匹配；多选支持任一包含、全部包含和集合相等；数字支持相等、大小比较及包含边界的区间。

规则按priority升序匹配，第一条命中后执行，只能跳到后续题或END。未命中进入下一题，末题默认结束。返回题号修改答案属于页面导航，不改变规则只能向后跳的限制。未到达的必答题可以合法跳过，实际到达的必答题必须作答。

同题、同操作符的数字条件按Decimal值去重，例如18与18.0、+18与1.8e1、等值区间端点和正负零。阈值原字符串保留，不经float或Decimal.normalize处理。gt与gte、不同阈值及相交区间仍按优先级执行，不进行跨操作符的重叠求解。

### 4.3 路径重算与答案清理

服务端从首题重放路径，遇到首道尚未保存的题停止。上游答案修改后，只保留本次重放实际经过的已保存答案，其后旧值清除，不自动恢复。

例如Q1选A跳到Q3且Q3已保存，改选B后先到尚未保存的Q2，即使Q3以后仍可能到达，Q3旧值也清除。完成Q2后须重新回答或显式跳过Q3，避免未经再次确认的旧答案进入统计。用户不能直接向隐藏分支写值，最终提交会再次验证整个路径。

页面显示被清除答案的题数、题号、题干和重新填写说明，使用文本节点渲染。短暂通知消失后仍可查看当前清理明细；下一次成功保存会更新提示，刷新或提交后不持久保留。

### 4.4 身份、权限与提交

所有管理和统计查询限定ownerId，分享链接只提供填写入口。填写者先登录，通过当前账号的问卷内HMAC伪名访问自己的记录。匿名答卷不保存identifiedUserId，创建者接口不返回respondentKey；系统运营者持有密钥时仍可能关联身份。APP_SECRET必须随已有数据妥善保留，第一阶段不支持无损密钥轮换。

密码使用Argon2id散列。会话Cookie采用HttpOnly和SameSite=Lax，HTTPS可启用Secure；数据库仅保存token散列。写请求检查CSRF令牌和Origin，会话有效性不依赖TTL立即删除。

草稿按status和revision条件更新，防止陈旧页面覆盖。正式提交只接受revision，不接受客户端整份答案或路径；已提交答卷不可覆盖，重试返回原回执。允许多次填写时应新建会话，禁止多次时由部分唯一索引限制同账号两个草稿的提交竞争。

<a id="concurrency"></a>

### 4.5 关闭与并发边界

采用D09-B方案：最终重放后读取问卷状态快照，检查开放状态、截止与版本，再对答卷执行单文档CAS更新。读到CLOSED的新提交被拒绝；读到开放快照的在途请求仍可能在关闭返回后落库，admittedAt也可能晚于closedAt。该方案没有跨文档原子关闭保证，截止也按所读快照判断，截止时间等于或早于admittedAt时拒绝提交。

这一选择可在standalone MongoDB上运行，降低事务与部署复杂度。若后续要求关闭返回后绝无新增正式答卷，需要调整并发方案。

<a id="statistics"></a>

### 4.6 统计口径

统计实时聚合对应contentVersion的SUBMITTED答卷，草稿、已清除分支和空值不计入有效回答。responseCount为正式答卷数，respondentCount为伪名去重账号数，不等同于自然人数。题目answerCount统计非空回答，reachedCount统计最终路径到达；选择题补齐零票选项，各选项分别提供次数和独立账号数。数字mean以字符串返回，空集为null，原始内容可分页遍历。多个查询之间不提供事务快照。

## 5 API说明

API前缀为/api，使用JSON。互动说明位于/docs，机器契约位于/openapi.json；接口导出见[test-results/final-20261021/http-dom/openapi.json](test-results/final-20261021/http-dom/openapi.json)。除注册、登录、健康检查外，业务API均要求登录。填写入口/survey/{shareSlug}是网页路由，页面会引导登录。

### 认证与错误

POST /auth/login返回user和csrfToken，并设置HttpOnly会话Cookie。后续写请求须同时携带Cookie和X-CSRF-Token。GET /auth/me可恢复当前用户和CSRF令牌。公开链接不提供管理权限；所有问卷管理和统计接口只允许创建者。Cookie不能在多个账号间混用。

业务错误使用 `{"error":{"code":"required","message":"此题必须回答","field":"q1"}}`。请求格式错误包含fields数组；401表示未登录或会话失效，403表示CSRF或来源失败，404表示不存在或无权访问，409表示状态/修订/重复提交冲突，413表示请求过大，422表示格式或业务校验失败，503表示未能确认数据库操作成功。收到503时，应按会话ID或幂等键读取结果后再重试。

### 路由与请求

下表路径省略/api，分页skip默认为0、limit默认为20且最大100。正常查询/修改通常返回200，注册、创建问卷和创建填写会话返回201。

| 方法 | 路径 | 请求与返回重点 |
| --- | --- | --- |
| GET | /health | 数据库ping成功时返回status=ok、版本与schemaVersion |
| POST | /auth/register | username、password；返回id和username，用户名规范化唯一 |
| POST | /auth/login | username、password；返回user、csrfToken和Cookie |
| GET | /auth/me | 当前账号与CSRF令牌 |
| POST | /auth/logout | 注销当前会话并清Cookie |
| GET | /surveys | skip、limit；返回items、total及分页信息，仅自己的问卷 |
| POST | /surveys | 完整问卷草稿定义；返回id、shareSlug、revision等 |
| GET | /surveys/{id} | 创建者获取完整定义与effectiveStatus |
| PUT | /surveys/{id} | 完整可编辑定义加revision，仅DRAFT；不接受ownerId、status等服务端字段 |
| POST | /surveys/{id}/publish | revision；完成定义校验并发布 |
| POST | /surveys/{id}/close | revision；关闭已发布问卷，保留数据 |
| PATCH | /surveys/{id}/deadline | revision、closesAt；时间含时区或null，不重开已结束问卷 |
| GET | /public/{shareSlug} | 登录者获得已发布定义与有效状态，关闭后可用于解释本人已保存答案 |
| GET | /public/{shareSlug}/my-attempts | 当前账号最近50次填写，供恢复进度或查看回执 |
| POST | /public/{shareSlug}/attempts | attemptKey、participationMode；创建或幂等获取一份填写 |
| GET | /attempts/{id} | 本人答卷、已保存答案、已到达路径、下一题与是否可提交 |
| PUT | /attempts/{id}/answer | revision、questionId、value；保存、重算路径、返回removedQuestionIds |
| POST | /attempts/{id}/submit | 仅revision；全路径校验、受理检查及正式提交；重试幂等 |
| GET | /surveys/{id}/stats | 有效答卷数、独立账号数、每题指标 |
| GET | /surveys/{id}/stats/{questionId} | 一道题的回答、到达、选项及均值指标 |
| GET | /surveys/{id}/stats/{questionId}/answers | skip、limit；完整回答分页，匿名不返回账号引用 |

### 定义与值的格式

草稿有title、description、anonymousEnabled、allowMultipleSubmissions、closesAt、questions。questions是数组，每题包含questionId、order、title、type、required、options、constraints、rules；完整字段见MongoDB导出Schema和OpenAPI。创建空问卷草稿允许，发布必须至少一题。最多200题、每题100选项及50规则。

options每项为optionId和label。题型SINGLE、MULTI、TEXT、NUMBER对应单选、多选、文本、数字。constraints字段按题型使用：多选minSelections/maxSelections，文本minLength/maxLength，数字minValue/maxValue/integerOnly。数字上下界采用十进制字符串。保存已发布定义返回definition_frozen。

规则为ruleId、priority、condition、target。condition包含op和value；单选eq的value为optionId，多选contains_any/contains_all/set_equals的value为非空optionId数组，数字比较value为十进制字符串，between为两项字符串数组。target是后续questionId或END，同题priority不能重复。JSON中的显示顺序不决定规则优先级。

答题value：单选一个optionId字符串，多选optionId数组，文本字符串，数字十进制字符串，如 `"18"` 或 `"0.1"`。显式跳过可选题可传null；多选空数组及文本/数字空白也视作留空。错误空类型拒绝。未知题、未到达的题、重复选项、越界或必答空值返回422。

### 完整调用顺序

注册并登录，保留会话Cookie和csrfToken；创建草稿，添加题目后通过PUT保存并取得新revision；发布后取得分享码。填写者另行登录，生成稳定attemptKey创建会话，按返回的nextQuestionId保存每题答案，每次使用最新revision。返回readyToSubmit=true时再提交。最终提交不接收整份客户端答案或路径，防止绕过逐题权限。

answer返回的visitedQuestionIds由服务端推导；removedQuestionIds表示此次上游修改清除的已保存答案。使用陈旧revision返回revision_conflict，应重新读取并让填写者确认当前内容。提交已经成功但回执丢失时，对同一填写ID再次提交可获取既有结果，关闭问卷后仍可读取成功回执。

### 统计响应

统计口径见[第4.6节](#statistics)。分页回答中的匿名行不返回identifiedUserId或respondentKey。

### 10.2 从四集合到十集合

第一阶段的题目只存在于单份问卷内部，没有跨问卷的全局身份；直接共享可变题目会使旧答卷含义随修改漂移。因此新增题目根、独立不可变版本、精确版本USE及个人题库成员，而填写仍读取原问卷快照。跨卷统计按来源解析同一确切版本，旧题经显式一致性关联加入，不批量改写历史数据。这个变化扩展了复用和追溯能力，保留了原单份问卷的读取、发布与提交边界。

原users、sessions、responses保留结构版本1；surveys使用严格v1/v2分支。普通本地题继续使用原格式；第一次明确导入库题时，草稿变为2并保存sourceRef。新答卷仍为结构1，按surveyId、contentVersion和本卷questionId解释，不依赖目录最新版本。

| 新集合 | 核心字段、内嵌与引用边界 |
| --- | --- |
| question_items | ownerId、name、status、headVersionId、nextVersionNo、revision及至多一份workingDraft；工作稿内嵌payload和baseVersionId |
| question_versions | root引用、versionNo、parentVersionId、derivedFromVersionId、restoredFromVersionId、operationKey、payload、contentHash、summaryPolicy；正式版本只插入/读取 |
| access_grants | questionVersionId＋granteeId的当前USE及revision、active、撤销时刻；没有逐卷AGGREGATE授权 |
| question_banks | 个人库名称、说明、ownerId、状态与revision，不内嵌不断增长的成员 |
| question_bank_items | bankId、libraryQuestionId、questionVersionId、position和revision；成员固定版本，升级不推送问卷 |
| legacy_question_links | 一个旧实例一个HEAD；关联/暂停/更正/恢复分别生成不可变REVISION，HEAD.currentRevisionId决定唯一有效关系 |

问卷仍内嵌题干、选项、约束、顺序与规则，使填写与校验可以完整读取；版本历史和多对多共享/成员关系独立存储，避免无限数组。sourceRef含题目根、版本、内容签名、告知策略和服务器确认时刻。题目根ID、版本ID、本卷questionId和问卷contentVersion具有不同含义，不能互换。

保留原统计、提交幂等、单次提交和会话TTL索引。新增根/版本号唯一、根/operationKey唯一、版本/账号唯一、题库/版本唯一、成员排序、问卷来源多键索引及旧关联HEAD/操作键的部分唯一索引。验证器见[mongodb-schema.json](mongodb-schema.json)，可执行定义在[运行Schema](../app/runtime_schema.py)；原四集合初始化在[schema.py](../app/schema.py)。

### 10.3 实现方法与一致性边界

新增library_service.py、bank_service.py、legacy_service.py、usage_service.py、library_stats.py及library_api.py。domain.py、attempt_service.py、问卷内stats_service.py和填答页面保持原功能；survey_service.py增加明确的结构分派和来源保护，editor.js以白名单DTO保存，不能上传伪造sourceRef。填写接口不向参与者返回目录来源。

题目版本保存先检查所有权、工作稿和基线，原子分配编号、插入不可变版本，再CAS推进根指针。并发时允许编号空隙或已保存分支而默认指针未推进，响应通过headAdvanced说明。相同operationKey和请求重试返回同一版本，改请求报冲突；响应统一从数据库读取，避免时间精度造成首次与重试结果不同。

版本导入按受理检查时的USE及告知确认执行，随后一次CAS保存完整草稿。撤销阻止新的读取、入库和采用，不能撤回已导入快照；已经导入的草稿可发布，后续有效回答仍按原告知范围汇总。题库成员不能绕过撤销。正文变化须新建版本后显式替换；替换保留本卷ID和规则，原规则不再合法时整体拒绝，不静默删除。

使用清单只返回他人问卷的稳定HMAC展示标识、版本、状态及实例信息；不返回真实surveyId、分享码、创建者身份或分卷贡献数量。另存产生新根，祖先作者不因此取得新根的使用/统计权。从已导入的自有快照另存时保留derivedFromVersionId，并同样检查新采用权。

旧关联仅接受冻结的schemaVersion=1问卷，由旧卷所有者明确确认。正文、选项ID/顺序及约束必须一致，数字阈值采用无损Decimal语义；不能按题名、选项文字或相似ID自动匹配。关联先插REVISION再CAS切HEAD；中断候选不生效，可在原预期仍成立时重试。SUSPEND退出统计，CORRECT只留下新指针，RESUME重新核验并确认；旧修订保留，问卷及答卷BSON不变。实际并发纠错测试证实仅一个指针切换成功，不会同时计入两个根。

这些都是单文档原子性与明确的多文档受理边界，不宣称跨集合事务或整次统计快照。第一阶段D09-B提交边界保持不变。

payload只含title、type、required、options及constraints；不含本卷ID、顺序和跳转。例：创建数字题“年龄”，constraints设minValue="0"、maxValue="120"；默认保存切点24/48/72/96。取得item.id和version.id后共享给指定账号，再在草稿导入并确认告知。编辑既有版本先PUT工作稿，再POST版本保存；恢复通过restore生成新ID。
